# Support

## Where to ask

After the public repository is configured:

- use the issue tracker for reproducible bugs and documentation gaps;
- use discussions for usage questions and design proposals; and
- use the private security channel for vulnerabilities.

The project does not yet claim a public support URL. Do not send requests to
the placeholder address in `DESCRIPTION`.

## What to include

Provide:

```r
sessionInfo()
packageVersion("readreq")
```

Also include the exact `release_id`, requested assets/view, parser version,
error class and a minimal example. Never attach an official workbook or cache
containing restricted material. A source URL and SHA-256 are normally enough
to identify the asset.

## Support boundaries

The project can help with package behaviour, supported source layouts and
reproducibility. It cannot provide legal advice about data reuse, guarantee
availability of government sites or support unaudited releases as if they
were validated.
